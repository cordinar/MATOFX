# MATOFX SPDM v2 — Roadmap

Living document tracking what's next, when. The source of truth for *decisions* is `PROJECT_BRIEF.md`; the as-built detail (per-feature module map, ship dates, migration list) is `ARCHITECTURE.md` §16. This file tracks *delivery*.

Build is structured into three phases: **Phase 0** lays the foundation; **Phase 1** ships an MVP for customer demo; **Phase 2** completes the locked v1.0 must-ship list from §I46.

**Status as of 2026-05-29.** Phase 0 ✅ done. Phase 1 ✅ done (exit criterion met — see `RUN_THE_DEMO.md` / `PHASE1_RELEASE_READINESS.md`). Phase 2 is well into delivery: workflows, approvals, compare, live jobs, parametric studies (scalar), hierarchy ADR-0002, multi-role capabilities, the file-library + materials-database catalogs, lineage (ADR-0010), workflow structure graph (ADR-0013), V&V tracking (ADR-0011), and KPI extraction (ADR-0012) are landed; SSO/MFA, backups, the broader install/i18n/observability work, and the v1.0 security hardening tail remain. **Scope expanded 2026-05-26** with five new ADRs (0008–0012) ruled into v1.0 at full scope — surrogate family + Model registry (✅ shipped 2026-06-03), optimisation framework (✅ shipped 2026-06-08), data lineage (✅ shipped 2026-05-27), V&V tracking (✅ shipped 2026-05-29), KPI extraction (✅ shipped 2026-05-29) — plus a smaller-feature-rows wave (auto-summaries with optional LLM enrichment, find-similar runs, auto-disable inactive users ✅ shipped 2026-05-26). The originally-listed "tool-preset save/recall" row was **dropped 2026-05-27** — descriptor-bundled author presets (shipped on the descriptor-wizard *Presets* tab) plus the existing *Previous job* and *Defaults* popovers cover v1.0's preset story without a user-saved DB table. Pilot date re-baselines once the surrogate / optimisation design docs land.

## Pacing principles

- **No v1.0 quality cuts.** The §H40 bar (must-be-exhaustively-tested modules + CI gating + performance commitments) does not trade against shipping speed.
- **Defer features, not quality.** Pressure → move things to v1.x; never lower the test bar or skip security work.
- **Phase 0 is non-negotiable.** Skipping foundation work to get to Phase 1 faster trades real days now for compounding rework later.
- **Phase 1 is the smallest demo, not the smallest product.** Every Phase 1 piece extends in Phase 2; nothing gets thrown away.
- **Review the must-ship list every couple of months** as build progresses; refine.
- **The brief is the source of truth for decisions; ARCHITECTURE.md §16 is the source of truth for as-built detail; this file is the source of truth for delivery progress.**

### Design-space coverage (ADR-0020) — hardened 2026-09-02/03

Built previously; driven end to end through the UI for the first time this session, which
found and fixed **eleven defects**. Shipped in the process:

Full account in `ARCHITECTURE.md` § *Coverage: where this feature stands*. One pre-existing

### Surrogate model detail + exported tool — hardened 2026-09-07

Driven through the UI on a `combined` model with a categorical factor
(*Finned Cold Plate - User runs surrogate*), which found **eight defects** in
the surrogate's two output surfaces. One theme: the synthesised artefact kept
the model's view of the world and dropped the tool's. Shipped:

- the **exported tool keeps the source tool's input rules** — integer-ness,
  precision, declared min/max, slider / radio widget, and cross-field sum
  checks — so the stand-in asks for a design the real tool would accept;
- a **categorical factor gets a picker**, not a numeric slider (it was sending
  `material = 0.5` and the viewer opened on a predict error), end to end
  through the API schema;
- **labels everywhere** on the model detail page and the field viewer — field
  outputs included, which the number-only resolver had skipped;
- the page **leads with the scalar fits**, and each half is its own card;
- four chart fixes: two plots that rendered as a slice of an axis, a redundant
  value-vs-node line beside a 3-D mesh, half-integer `POD mode` ticks, and a
  mode-coefficient caption that made a (correct) negative bar read as a fault.

Full account in `ARCHITECTURE.md` § *A surrogate stopped being the tool it
stood in for*.

### Optimisation: "Track only" responses are reported — 2026-09-07

A `goal: track` response was collected on every run and written to its
`study_result` row, but every result surface on the study page was built from
the optimised responses alone — so it could be read on the job page, in Compare
or via a cohort, and nowhere on the study that declared it. Shipped:

- tracked columns in the **Runs** table and its **CSV**, after the goals;
- tracked columns in the **Best designs / trade-off front** table, which is
  where they matter most — separating designs that tie on the goals;
- a **TRACKED** section in the design-space explorer's axis and colour pickers.

They take no part in the Pareto front, the weighted score or the ranking, and
two tests pin that those are byte-identical with and without them. The help
chapter now also explains how the **weighted score** is computed (min-max
rescale per goal → flip maximise → weight → sum), which was undocumented.

Full account in `ARCHITECTURE.md` § *"Track only" was recorded everywhere except
where it was declared*.
